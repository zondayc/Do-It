# Do It

离线打卡与提醒应用。黑白线条、卡片布局，默认使用简洁的功能文案。

## 功能

- 每天、每周指定日、间隔 1–365 天、指定日期一次执行。
- 可选任务时间。设置时间后可选择是否提醒；关闭提醒不影响打卡。
- 每个任务的连续打卡天数，以及当天所有应执行任务都完成的全勤连续天数。
- 今日完成进度、月历记录、补记和撤销。
- 暂停和归档任务。历史任务安排与打卡记录保留。
- 每日截止时间可设为 00:00–06:00，适合跨零点作息。
- 30 种黑白线条图标，默认显示前 8 个，可展开全部。长按拖动排序，顺序保存在本机；也可使用「调整顺序」中的前移、后移。
- 手机长按任务或便签可选择编辑、删除。短按和滑动不会打开菜单，长按后的松手不会误打卡。
- 应用内时间滚轮、日期日历和周期选择，替代系统默认控件。
- 独立便签页：一次性任务，可不设日期，或设置日期、时间、提醒。便签独立统计，不影响全勤；完成后停止提醒，撤销后恢复待完成。
- 自定义任务模板：新建、编辑、删除和套用，保存图标、周期、时间、备注、提醒。修改模板不影响已创建任务，套用时重新计算间隔起点和单次日期。
- JSON 备份导出与恢复。恢复前保留一份原数据。
- 无账号、无云同步、无第三方网络请求。Android 未声明互联网权限。

## 使用

GitHub 仓库保存源码、图标和构建脚本。安装包与本机测试数据不提交到仓库，安装包在本地构建后生成。

Mac 安装包在 `dist/Do-It-0.1.1-mac-arm64.zip`。解压后把 `Do It.app` 放入自己的应用目录并打开。此版面向 Apple Silicon Mac，最低 macOS 14；开发与运行验证使用本机 macOS 26.6.2。

Android 安装包在 `dist/Do-It-0.1.1.apk`。发送到手机后打开安装。此版最低 Android 8，目标 Android 15，没有依赖特定 CPU 的原生库，可用于 arm64 手机。APK 为本地开发签名版本。

首次启动没有预置个人任务。可以新建任务，也可以主动添加三个示例任务。

## 提醒

Mac 在「设置 → 系统提醒」中允许通知。使用系统通知和提示音；不会在系统专注模式、通知关闭、睡眠或关机时承诺准时响铃。关闭窗口后应用留在菜单栏，退出需用菜单或 Command-Q。最多预排后续 60 条任务提醒，应用运行期间和重新打开时会续排，因此长期完全退出会耗尽已经排好的提醒。

Android 在应用设置中分别允许通知和「闹钟和提醒」。准时权限开启后使用系统 AlarmManager 的闹钟 API，接入开机、改时间和改时区后的重新安排。响铃最多 60 秒，通知可停止、直接打卡或推迟 10 分钟。未获准时权限时退为可能延迟的普通通知。没有全屏锁屏闹钟界面。

在 Redmi K90 Pro Max 上，还需按手机实际系统入口允许自启动，并把 Do It 的电池策略设为「无限制」。没有连接该型号实机，本次未完成实机安装、熄屏、重启、待机响铃与帧率验证。

## 统计规则

1. 只计算当天安排的任务。新建任务不会反向影响过去。
2. 单任务连续数按连续完成的应执行日累计，休息日和暂停日跳过。
3. 全勤连续数按当天全部应执行任务均完成的日期累计；无任务日跳过。
4. 今天未完成时保留此前的连续数；过去应执行日漏打则中断。
5. 补记、撤销会重算当前和最长连续数。
6. 修改、暂停、归档从当天生效，历史修订保留。当日安排变动会影响当日全勤。
7. 一天开始时间改变后，已有打卡日期不移动。早于截止时间的提醒属于上一任务日，例如截止 04:00，10 月 3 日 01:00 的提醒属于 10 月 2 日。

## 数据

Mac 数据在 `~/Library/Application Support/Do It/state.json`。恢复前副本在同目录 `before-import.json`，再次恢复会更新该副本。

Android 数据在应用私有存储，恢复前副本在同一私有存储中。卸载前先导出备份。Mac 与 Android 的数据各自独立，可通过 JSON 备份手动迁移。

读取或校验失败时不覆盖原记录。有效版本为 schema 1，兼容旧备份，新增字段在加载时补全。任务和便签合计上限为 200，已删除项目也计入；模板上限为 100。删除任务从当天停止安排，历史打卡仍保留。图标顺序、便签和模板随 JSON 备份一起迁移。

## 开发

共用界面在 `web/`，使用原生 JavaScript、CSS 与 SVG 图标。Mac 使用 AppKit/WKWebView、UserNotifications 和原子文件保存；Android 使用系统 WebView、本地资源拦截、应用私有存储、AlarmManager 和响铃前台服务。运行时没有服务器、框架下载或外部字体。

```sh
node --test tests/*.test.cjs
node tests/performance.cjs
bash scripts/build-mac.sh
bash scripts/build-android.sh
```

Mac 构建需要 Apple Command Line Tools，使用本机 Swift 编译器，不依赖完整 Xcode。

Android 构建使用缓存的 Temurin JDK 17、Google Android API 35 platform 和 build-tools 35。本机缓存为 `~/.cache/doit-build`，无需改动系统 Java。可通过 `DOIT_BUILD_CACHE`、`DOIT_JDK`、`DOIT_ANDROID_TOOLS`、`DOIT_ANDROID_PLATFORM` 指定位置。构建脚本使用 aapt2、javac、D8、zipalign 和 apksigner，无 Gradle 外部依赖。Mac 上的 Google 打包工具使用系统 Rosetta。

Mac 可通过 `DOIT_DATA_DIR=/absolute/path` 隔离测试数据。开发用 `--preview-phone` 参数以 448px 窗口查看响应式界面。验证数据放在 `build/qa-data/`，不混入正常用户数据。

## 验证与性能

逻辑测试覆盖日循环、周末跳过、间隔执行、单次日期、历史修订、暂停、归档、全勤、跨零点、提醒取消、补记、撤销和无效备份。具体结果见 `docs/verification.md`。

统计复用日历日期序列并一次遍历完成当前、最长和累计统计。打卡只复制对应任务的记录，界面按已有节点更新，保留焦点与滚动位置。系统提醒采用按事件触发的原生服务，避免持续轮询。Mac 低频检查日期边界时不再读取整个历史文件。

200 个任务、730 天、137,400 条记录的模型压力样例，五次完整统计的本次中位数约 17.5ms。本数值来自本机 Node.js 运行时，不能等同于 Android 实机的端到端点击延迟或帧率。

较大历史数据仍整体序列化为 JSON，原生存储往返未做大型样例测试。后续若实际记录量明显增大，应将存储改为 SQLite，并测试端到端响应、内存和备份耗时。
